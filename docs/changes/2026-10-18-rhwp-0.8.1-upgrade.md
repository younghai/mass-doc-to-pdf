# rhwp 엔진 업데이트 (rhwp-python 0.8.0 → 0.8.1)

2026-10-18. PyPI `rhwp-python` 최신(0.8.1, 2026-07-07 게시)을 반영했다.
업스트림 `edwardkim/rhwp` 최신 릴리스는 v0.8.7(2026-10-06)이지만, 본 프로젝트가
소비하는 Python 바인딩(rhwp-python, 커뮤니티 패키지)의 최신이 0.8.1이므로
여기까지가 현재 설치 가능한 상한이다. 바인딩 릴리스가 상류를 추격하면 후속 범프.

## 배경

- 기존 핀: `rhwp-python==0.8.0` (2026-06-21, 코어 0.7.16).
- 최신: `rhwp-python==0.8.1` (2026-07-07, PATCH) — 코어 **0.7.17**.
- 0.8.1은 바인딩 코드 변경 0(테스트 1파일 + 문서/버전만)의 PATCH 릴리스.
  공개 API / IR schema("1.1") 불변. 상류 HWPX serializer fidelity 개선
  (edwardkim/rhwp#1451 shapeComment 직렬화 수정)을 흡수.

## 변경

- `apps/api/Dockerfile` — pip 핀 0.8.1, freetype 워크어라운드 주석 갱신.
- `standalone/scripts/install-ubuntu.sh` — `RHWP_PYTHON_VERSION` 기본값 0.8.1,
  freetype 주석 갱신.
- `standalone/scripts/install-rhwp-worker.sh` — 0.5.1 → 0.8.1 (이 헬퍼는
  0.8.0 범프 때 누락되어 0.5.1에 머물러 있었다).
- `docs/local-development.md` — 설치 명령·본문 버전 갱신.
- `apps/api/src/convert/workers/rhwp_worker.py` — 폰트 API 부재 NOTE의
  확인 버전 범위를 0.8.1까지로 갱신.

## 호환성 검증 (wheel 직접 검사)

- **API 동일**: `parse` / `export_pdf` 시그니처 변화 없음. `dir(rhwp)`에
  폰트 관련 진입점 여전히 부재(`set_font_paths` 등) — 워커의 hasattr 프로브는
  여전히 no-op이고 실제 폰트 해석은 `ttfs/hwp` cwd 심링크 + fontconfig 그대로.
- **freetype 워크어라운드 유지**: 0.8.1 manylinux x86_64 휠은 0.7.0/0.8.0과
  **바이트 동일한** `libfreetype-c0e61f0c.so.6`를 번들하고, aarch64 휠은
  `libfreetype-eea08430.so.6`(해시 상이)를 번들한다. 양쪽 모두
  `FT_Palette_Select` 심볼 부재(nm -D로 확인). Dockerfile/install-ubuntu.sh의
  `libfreetype-*.so.6` glob은 두 아키텍처 모두 매칭 — 워크어라운드 그대로 유효.

## 런타임 검증 (2026-10-18, macOS arm64 / Python 3.12)

`tmp/local-runtime` venv를 0.8.1로 업그레이드 후 `rhwp_worker.py`로 실측:

- 스모크: `localhost-smoke.hwp`(14p, 989,898B) / `localhost-smoke.hwpx`(2p,
  98,441B) 변환 성공, PDF 1.7 유효.
- 품질 코퍼스(`tmp/preview-objects` 11건, unique 5종): 0.8.0 대비 페이지 수·
  추출 텍스트 전량 일치 4종. 1종(중소기업 감면 신청서류, 1p)은 줄바꿈 위치만
  변동(단어·페이지 수 동일, 121,034→120,816B) — 상류 조판 개선 반영, 회귀 아님.
- **OPEN-001 미해결 확인**: "보고서 양식.hwp"는 0.8.1(코어 0.7.17)에서도
  `LAYOUT_OVERFLOW: type=PartialTable`로 실패. 0.8.0과 동일 — 상류
  리포트/추적 대상 그대로.
