# rhwp-cli v0.9.0 범프 + 품질 임계값 실측 재보정

2026-11-12. 상류 `edwardkim/rhwp` v0.9.0(2026-11-08, "PDF 가져오기와 Rust·CLI
배포") 릴리스에 맞춰 CLI 핀을 v0.8.7 → v0.9.0으로 올렸다. rhwp-python은
여전히 0.8.1이 최신(PyPI)이라 Python 워커 경로는 무변경.

## v0.9.0 검증 (macOS arm64, 실측)

- `rhwp-v0.9.0-macos-aarch64.tar.gz` SHA256SUMS.txt 대조 일치
  (`5993462a…f11974`). 릴리스 자산 명명 규칙·SHA256SUMS.txt 유지 →
  설치 스크립트 경로 그대로 호환.
- `rhwp --version` → `rhwp v0.9.0` (preflight semver 파싱 호환).
- `export-pdf <input> -o <output>` 시그니처 유지 (`RhwpCliConverter` 호환).
  신규 `import-pdf` 서브커맨드 추가(우리 미사용).
- **OPEN-001(보고서 양식.hwp) 회귀**: exit 0 · `LAYOUT_OVERFLOW` 0건 ·
  PDF 1.7 2페이지 — v0.8.7에서 확보한 동작 유지.
- 코퍼스 회귀: 사업계획서.hwp 14페이지 정상, 감면신청서류 1p(122,464B)·
  7p 문서(387,134B) 변환 정상.

## v0.9.0 렌더 변경 3가지 (실측)

1. **파일 크기 급감(폰트 서브셋팅 개선)**: 희소 양식 44,273B → 22,603B,
   7p 문서 529KB → 387KB.
2. 텍스트 추출 개선: 제목의 글리프 간 공백 정규화("신 사 업"→"신사업"),
   단어·글자수(407자) 완전 보존.
3. 페이지 높이 미터릭 ~0.1% 변화(MediaBox 반올림, 100dpi 래스터 1170→1169px)
   — 서브픽셀 래스터 차이로 픽셀 diff 4.1% 관찰되나 콘텐츠 무변화
   (시프트 가설은 dy 비교로 부정, 텍스트 층 동일성으로 판정).

## 품질 임계값 재보정 (필연적 후속 조치)

- 문제: `RHWP_CLI_MIN_PDF_BYTES` 32KB 바닥(quality.ts)이 v0.9.0의 정상
  출력(22.6KB)을 `rhwp_small_pdf_review` → status **review**로 강등.
  범프만 하면 OPEN-001류 문서가 v0.8.7 대비 성능 퇴화.
- 실측 근거: 정상 문서 최소 22.6KB(희소 양식) vs 퇴화/공백류 출력 수KB.
- 변경: 32KB → **16KB** (정상 최소와 공백류 사이 실측 기반 마진).
  페이지당 4KB 규칙은 무변경(다중 페이지 공백 방어 유지).
- 테스트 2건 추가: 22.6KB급 정상 양식 → passed(경고 없음),
  10KB 퇴화 출력 → review 유지. 기존 11건 포함 13/13 통과.
- 다음 rhwp 범프 시 임계값 재실측 절차는 quality.ts 주석에 명시.
