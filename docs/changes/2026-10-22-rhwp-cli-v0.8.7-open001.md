# OPEN-001 해소 확인 + rhwp-cli 핀 v0.7.17 → v0.8.7

2026-10-22. OPEN-001("보고서 양식.hwp" PartialTable LAYOUT_OVERFLOW 변환 실패)가
상류에서 해결된 것을 실증했고, rhwp-cli 설치 핀을 v0.8.7로 올렸다.

## 상류 해결 경위

- 우리가 제출한 edwardkim/rhwp#1583이 **CLOSED (COMPLETED)**.
- 상류 협업자(jangster77)가 원인을 코드 판독으로 확정: PageDef가 0(구역정의
  누락/손상)이면 `content_bottom=0` → 전 블록 overflow(`bottom=0.0`) + 0크기 SVG.
- 수정: 렌더링측 A4/기본여백 폴백으로 PDF 변환이 항상 유효 크기로 진행되도록
  변경(IR 불변). PR #1817(원 PR #1783, 반영 커밋 `e92ce595`)로 머지.
- rhwp-python 0.8.1(코어 0.7.17)은 수정 커밋 이전 스냅샷이라 미포함 —
  2026-10-18 재테스트에서 여전히 동일 실패 확인.

## 실증 (2026-10-22, macOS arm64)

- `rhwp-v0.8.7-macos-aarch64.tar.gz` 다운로드 → `SHA256SUMS.txt` 대조 일치
  (`6ed46aa6…43662d`) → 설치.
- `rhwp --version` → `rhwp v0.8.7` (preflight `--version` 파싱 호환).
- **OPEN-001 원본 파일 변환 성공**: `export-pdf` exit 0, stderr에
  `LAYOUT_OVERFLOW` 0건(0.7.17에서는 31페이지 전체에서 발생), PDF 1.7 · 2페이지
  · 44,273B · "OOO 신사업 보고서" 양식 본문 정상 추출.
  - 참고: 0.7.17의 "31페이지"는 높이 0 레이아웃이 만든 오버플로 페이지 수.
    폴백 적용 후 실제 조판은 2페이지.
- 일반 문서 회귀: 사업계획서.hwp(14p) 변환 exit 0 · 14페이지 정상.
- CLI 인터페이스 확인: `export-pdf <input> -o <output>` 시그니처 유지
  (`RhwpCliConverter.args`와 일치).

## 후속 (범위 밖)

1. **운영 반영**: rhwp-cli를 실제 체인에 넣으려면 운영 서버에서
   `install-rhwp-cli.sh` 실행 + `.env.standalone`에 `RHWP_CLI_ENABLED=1`.
   기본값은 그대로 0(오프) — 코퍼스 품질 리포트로 검증 후 켜는 기존 운영
   절차 유지.
2. **rhwp-python 추적**: v0.8.x 코어 번들 릴리스가 나오면 Python 워커 경로도
   자동 해제. 바인딩 저장소(DanMeon/rhwp-python) 릴리스 모니터링.
3. **상류 이슈 코멘트**: 원본 파일로 v0.8.7 검증 결과를 #1583에 회신(폴백
   발동·실제 페이지네이션 확인 근거 제공).
