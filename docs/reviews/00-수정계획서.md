## 3. 실행 단계 (Phased Roadmap)

### Phase 0 — 배포 게이트 (P0 전량) · 목표: "외부 공개 차단 해제"
순서: **P0-1 → P0-4 → P0-2 → P0-3 → P0-5**
- P0-1 먼저(엔진 신뢰의 근간), 그다음 P0-4(보안 기본선)로 인프라를 잠근다.
- P0-2는 결정(승격/격리/폐기)이 선행 — 가장 빠른 안전 조치는 `VITE_ENABLE_MEETINGS` 플래그로 외부 빌드 제외.
- 완료 기준: 인라인·큐 동일 판정 테스트 통과 / 외부 빌드에 Meetings 부재 / 약관·개인정보 페이지 존재 / nginx 보안 헤더·TLS·파트 제한 적용 / 랜딩에 품질 차별점 노출.

### Phase 1 — 출시 품질 (P1 전량) · 목표: "공개해도 부끄럽지 않은 사용성"
순서: **P1-4 → P1-5 → P1-6 → P1-7 → P1-1 → P1-3 → P1-2**
- 저비용 고효과(P1-4/5/6/7)를 먼저 처리해 빠르게 신뢰도를 올린 뒤, 가치 핵심(P1-1)과 UX 무거운 항목(P1-2/3)으로.

### Phase 2 — 운영 성숙 (P2) · 목표: "운영자 협업 도구 완성"
- P2-1(검수 워크플로우)이 제품 차별점을 실제로 완성하는 항목 — Meetings보다 우선. P2-2~8은 병렬 가능.

### Phase 3 — 부채·전략 (P3)
- 상시 처리. P3-5(Meetings 전략)는 Phase 2 착수 전 의사결정 권장.

### ✅ P0-4 보안 배포 기본선 — 2026-07-05 완료(코드/설정) · TLS는 배포 시
- **문제:** `trustProxy: true` 하드코딩으로 X-Forwarded-For 전체 체인을 무조건 신뢰(rate limit 우회 가능, [SEC-01/DEV-02]) + README가 안내한 `TRUST_PROXY` 토글이 코드에 없음(드리프트) + 멀티파트 파트 수 무제한([SEC-05]) + nginx 보안 헤더 전무([SEC-02]).
- **수정:**
  - `config.ts` — `parseTrustProxy()` 추가. 기본 **1홉**(nginx 단일 프록시), `TRUST_PROXY=0`→끔, `N`→N홉, `true`→전체 체인(다단 프록시 opt-in). `AppConfig.trustProxy`로 노출.
  - `app.ts` — Fastify `trustProxy: deps.trustProxy ?? 1`로 교체(하드코딩 제거). 멀티파트 `limits`에 `files:1, fields:8, parts:12` 추가.
  - `server.ts` — `cfg.trustProxy` 주입.
  - `apps/web/nginx.conf` + `standalone/nginx/*.conf.in` — `X-Frame-Options`/`X-Content-Type-Options`/`Referrer-Policy`/`HSTS`/`CSP`(앱이 외부 리소스 미사용이라 타이트하게) 추가.
  - `README.md` — `TRUST_PROXY` 환경변수 표·운영 주의 갱신(드리프트 해소).
- **검증(TDD):** `config.test.ts`에 trustProxy 5케이스 선작성(RED)→구현(GREEN). 전체 API 테스트 **141 passed / 1 skipped**, 3개 워크스페이스 typecheck 0 error. nginx는 로컬 미설치라 `add_header` 지시자 육안 검토(표준 문법).
- **남은 것(배포 시):** nginx TLS 종단(`listen 443 ssl` + 인증서)과 80→443 리다이렉트는 인증서가 필요한 배포 작업이라 코드 커밋 대상에서 제외 — [SEC-06]로 배포 런북에 반영 필요.
- **변경 파일:** `config.ts`, `config.test.ts`, `app.ts`, `server.ts`, `apps/web/nginx.conf`, `standalone/nginx/mass-doc-to-pdf.conf.in`, `README.md`.
