## 요약

이 규모의 개인 프로젝트로는 **이례적으로 성숙한 코드베이스**다. 엔진 체인/레지스트리 설계, DB 기반 큐의 claim 리스(lease)와 attempt(실패 회계)를 분리한 재시도 로직, 라운드로빈 공정성, 부팅 preflight로 미설치 엔진을 체인에서 제외하는 처리, ReDoS를 의식한 품질 검사기 등에서 시니어 수준의 설계 의도가 분명하다. 보안 역시 SQLi·IDOR·커맨드 인젝션·경로 조작·XSS 같은 핵심 위협을 정면으로 방어하고 있어 **Critical 취약점이 0건**이다.

그러나 운영 신뢰도를 갉아먹는 결함이 있다. 가장 치명적인 것은 **인라인 모드와 큐 모드가 품질 게이트를 서로 다르게 적용해, 동일 파일의 최종 상태(success/failed)가 배포 모드에 따라 달라진다**는 점이다. 여기에 README에 문서화됐지만 코드에 없는 `TRUST_PROXY` 토글, 1,000개 배치 시 브라우저 직렬 업로드 + 종료 없는 폴러라는 처리량 병목, 보안 응답 헤더 전면 부재가 더해진다.

**전체 코드 품질 등급: B+** — 핵심 변환 경로는 견고하나, 두 실행 경로의 동작 분기와 문서-코드 드리프트가 프로덕션 신뢰도를 떨어뜨린다.

**보안 위험도:** 내부 운영 시 **LOW**, 외부 공개 배포 시 **MEDIUM** (Critical 없음, High 2건).

## 잘된 점

- **큐 설계가 교과서적이다.** `apps/api/src/queue/jobQueue.ts:100-124`의 optimistic claim, claim=lease / attempt=real-failure 분리(`:101-114`, `retryOrGiveUp :198-217`), 라운드로빈 공정성(`:161-171`), 크래시 복구(`requeueStale`)까지 주석과 구현이 일치한다.
- **엔진 preflight 후 체인 제외.** `apps/api/src/convert/preflight.ts:143-150` + `registry.ts:72-93` — 미설치 rhwp/chrome가 "실패 시도"로 기록돼 전 변환을 `review`로 강등하던 문제를 구조적으로 차단. README의 2026-06-11 품질게이트 수정이 실제 반영됨.
- **품질 검사기의 ReDoS 방어.** `apps/api/src/convert/quality.ts:53-72`의 상호배타 분기 + 유계 반복 + 스캔 상한. 656KB PDF가 CPU를 수 분 점유했던 회귀를 주석으로 근거화하고 방어한다.
- **타임아웃 전파가 전 경로에 있다.** sidecar `AbortSignal.timeout`(`h2orestart.ts:399`), builtin `SIGKILL`(`:437`), rhwp `execFile timeout`(`rhwp.ts:71`) — 변환 엔진 hang을 모든 엔진에서 차단.
- **보안 방어선이 견고하다.** 모든 job 라우트가 `where: { id, userId }`로 소유자 스코프를 강제해 IDOR가 없고(`jobService.ts:112-134`), 모든 외부 프로세스 호출이 `execFile` + 인자 배열 + `mkdtemp` 경로라 셸 경유가 전무하다. `dangerouslySetInnerHTML`/`eval` 싱크도 없다.
- **DTO 규율.** `MAX_UPLOAD_BYTES`가 shared에 단일 정의되어 서버 multipart 한도(`app.ts:64`)와 클라이언트 검증(`BatchUpload.tsx:64`)이 같은 상수를 소비한다. web/api 타입 drift 없음.

### [DEV-06] SQLite 다중 라이터 경합 (대량 배치 운영 상한)
- **심각도: Medium** · **작업 규모: M(Postgres) / S(문서+가드)**
- 위치: `apps/api/src/db.ts:15-22`, `apps/api/prisma/schema.prisma:5-8`

### [DEV-13] e2e 커버리지 부족 + CI 미연동, deploy가 CI를 게이트하지 않음

## 발견 사항 (보안)

> Critical 0건 · High 2건 · Medium 5건 · Low 3건. 아래는 요약이며 상세 재현·수정 코드는 원 감사 항목 기준.

### [SEC-01] `trustProxy: true` 하드코딩 → X-Forwarded-For 스푸핑
- **심각도: High** — [DEV-02]와 동일 근원. 공개 배포에서 API 포트 직접 노출 시 rate limit·IP 로깅 전면 우회. `X-Forwarded-For`를 매 요청 위조하면 `@fastify/rate-limit`의 키(`req.ip`)가 매번 달라져 인증 브루트포스·자원 고갈이 가능하다.
- 위치: `apps/api/src/app.ts:62`

### [SEC-02] 보안 응답 헤더 전면 부재 (CSP / X-Frame-Options / HSTS / Referrer-Policy)
- **심각도: High** (공개 배포 기준)
- 위치: `apps/web/nginx.conf:1-21`, `standalone/nginx/mass-doc-to-pdf.conf.in:1-20` — 두 파일 모두 `add_header` 없음.
- 문제: 현재 XSS 싱크는 없으나, 회의록/미리보기에 마크다운 확장이 추가되면 CSP 부재로 즉시 XSS화, `<iframe>` 임베드로 로그인 클릭재킹, HSTS 부재로 SSL stripping이 가능해진다.
- 수정: 두 nginx conf `server {}`에 `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Strict-Transport-Security`, `Content-Security-Policy`(Google 프로필 이미지·오디오 blob·PDF origin 반영) 추가.

### [SEC-03] SSH 배포 시 시크릿이 원격 셸 커맨드라인에 인라인 전개
- **심각도: Medium**
- 위치: `.github/workflows/deploy-ssh.yml:59-61`, `:46-47`
- 문제: `secrets.GHCR_TOKEN`이 원격 heredoc에 문자열 리터럴로 치환돼 `/proc/<pid>/cmdline`·셸 히스토리에 노출 가능. `.env.production`(AUTH_SECRET·GOOGLE_CLIENT_SECRET 포함)이 원격에 기본 umask로 남는다.
- 수정: 시크릿을 `env:`로 주입, `umask 077`, 배포 후 원격 `.env.production`에 `chmod 600`.

### [SEC-04] systemd 유닛 하드닝 부재 + `.env.standalone` 파일 권한 미설정
- **심각도: Medium** (standalone systemd 배포 시 차단 항목)
- 위치: `standalone/systemd/*.service.in`, `standalone/scripts/install-systemd.sh:26-33`
- 문제: 문서 파서(LibreOffice/Java/rhwp)가 신뢰 불가 입력을 처리하는데 프로세스 격리(`NoNewPrivileges`/`ProtectSystem`/`PrivateTmp`)가 없어 파서 익스플로잇 시 blast radius가 크다. 서비스가 sudoer(`SUDO_USER`)로 실행되고 `.env.standalone`에 `chmod`가 없다.
- 수정: 각 유닛에 `NoNewPrivileges=yes` `ProtectSystem=strict` `ReadWritePaths` `PrivateTmp=yes` `MemoryMax=2G` 등 추가, install 스크립트에 `chmod 600 .env.standalone`, 전용 서비스 계정.

### [SEC-05] 멀티파트 파트 개수 미제한 (자원 고갈)
- **심각도: Medium** · 위치: `apps/api/src/app.ts:64`
- 문제: `fileSize`만 제한되고 `files`/`parts`/`fields` 제한이 없어, 수천 개 파트를 담은 요청으로 저비용 DoS가 가능하다.
- 수정: `limits: { fileSize, files: 1, fields: 5, parts: 10 }`.

### [SEC-06] nginx TLS 미종단 + SSRF 아웃바운드 allowlist 부재
- **심각도: Medium** · 위치: `apps/web/nginx.conf:2`, `standalone/nginx/...conf.in:2`
- 문제: 제공된 nginx conf에 HTTPS 블록이 없다(80만 listen). SSRF 표면(`probeHttp`, sidecar/gotenberg URL)은 현재 사용자 입력이 URL로 흐르지 않아 직접 악용은 불가하나, 사이드카가 문서 내 외부 참조를 fetch하면 내부망 스캔 여지가 있다(SEC-04 격리로 완화 대상).
- 수정: 운영 nginx에 `listen 443 ssl` + 80→443 리다이렉트 명시, 사이드카/Gotenberg는 내부 네트워크에만 바인딩.

### [SEC-07] 개발 dependency에 Critical/High 취약점 (vitest/vite/jsdom/esbuild)
- **심각도: Medium** (개발/CI 환경 한정, 운영 런타임 미노출)
- 근거: `pnpm audit` — `vitest`(critical, <3.2.6), `jsdom>form-data`(high), `vite`(high/moderate), `esbuild`(low). 전부 devDependencies. **운영 감사(`--prod`)는 클린.**
- 수정: `pnpm up -D vitest@latest vite@latest jsdom@latest tsx@latest esbuild@latest` 후 재감사. `.github/dependabot.yml` 자동 병합 정책 확인.

### [SEC-08] Meetings 실시간 전사가 브라우저 SpeechRecognition으로 오디오를 외부(Google 등)로 전송 — 프라이버시
- **심각도: Low (Info)** · 위치: `apps/web/src/pages/meetings/MeetingLiveCapture.tsx:121-124`
- 문제: 서버 취약점은 아니나, Web Speech API는 오디오를 브라우저 벤더 클라우드로 전송한다. "기밀 회의록" 성격상 동의·고지 필요.
- 수정: 전사 시작 전 "브라우저가 음성을 외부 서비스로 전송할 수 있음" 동의 UI, 또는 온디바이스 전사.

### [SEC-09] 사이드카 오류 응답에 LibreOffice stderr 노출 (정보 노출)
- **심각도: Low** · 위치: `hwp-sidecar/app.py:58`
- 문제: 변환 실패 시 LibreOffice stderr 500자를 클라이언트로 반환 → 경로·버전 노출. (API가 다시 200자로 감싸 최종 노출은 제한적이나 사이드카 직접 접근 시 전량.)
- 수정: 클라이언트엔 일반 메시지만, stderr는 서버 로그에만 기록. (프론트 노출은 [DSN-03] 참조 — UX 문제이기도 함)

### [SEC-10] 로컬 개발 `.env`에 실제형 시크릿 존재 (추적은 안 됨)
- **심각도: Low** · 위치: 저장소 루트 `.env`
- 상태: `git ls-files` 미추적·히스토리 없음·이미지 미유입 확인(Dockerfile에 `COPY . .` 없음). 현 유출 경로는 없음.
- 수정: `.dockerignore`에 `.env`/`.env.*`(단 `!.env.example`) 추가, Google 시크릿이 실제 발급값이면 예방적 로테이션.
