## 전체 인상 (First Impression)

랜딩·업로드·큐·대시보드로 이어지는 **핵심 변환 경로의 디자인은 깔끔하고 일관된 라이트 SaaS 톤**(블루 액센트 `#2f5fd8` 계열, 화이트 카드, 회색 배경)이다. 정보 구조도 명료하다. 그러나 세 가지가 첫인상을 훼손한다:

1. **회의록(WIP) 화면이 완전히 다른 디자인 언어**(다크+골드 테마, 별도 브랜드명 "Bzengage Minutes / Whisper Meeting OS")로, 같은 앱이라고 믿기 어려울 만큼 이질적이다.
2. **제품의 핵심 차별점("변환 성공이 아니라 품질을 판정한다")이 어느 화면에서도 시각적으로 드러나지 않는다.** 랜딩은 평범한 "문서→PDF 변환기"로만 보인다.
3. **모바일에서 네비게이션이 붕괴**(햄버거 없이 각 항목이 2줄로 깨짐)한다.

가장 큰 기회: **품질 게이트(passed/review/failed)를 제품의 시각 언어 중심에 올리는 것.** 이것이 경쟁(클라우드컨버트·한컴독스) 대비 유일한 차별점인데 현재 UI는 이를 숨기고 있다.

## 시각 위계 (Visual Hierarchy)

- **가장 먼저 눈에 들어오는 것:** 랜딩은 거대한 "hwptopdf" 워드마크. → 제품명보다 **가치(무엇을 해주는가)**가 먼저 와야 한다. 부제 "HWP와 Office 문서를 운영 큐에서 PDF로 변환"의 "운영 큐"는 사용자 언어가 아니다.
- **대시보드 위계 부재:** 6개 스탯 카드가 모두 동일 크기·비중이라 무엇이 중요한지 알 수 없다. 실패 1건짜리 도넛 차트가 화면 절반을 차지한다. 대량 운영 도구인데 **시계열/추세가 없는 정적 스냅샷**이다.
- **랜딩 목업 통계의 오해 소지:** 히어로 우측 카드에 "성공률 94%"가 실데이터처럼 표시되나 하드코딩 예시다. "예시" 라벨이 없어 신뢰를 오도할 수 있다.

권장: 대시보드는 (1) 성공률/저품질 비율을 큰 1차 지표로, (2) 나머지를 2차 카드로 위계화하고, (3) 최근 7/30일 추세 라인을 추가. 랜딩 히어로 카피를 "변환 성공 여부가 아니라 *품질*을 판정합니다"로 교체.

## 접근성 (Accessibility)

- **색상 단독 의존:** 상태 배지(실패=빨강, 성공=초록 pill)가 색으로만 구분되는 경향. 텍스트 라벨은 있으나 색맹 사용자를 위해 아이콘/패턴 병행 권장.
- **텍스트 오버플로우:** 회의록 히어로의 "Speaker labels · timestamps · action item[s]"가 우측에서 잘림 — 컨테이너 오버플로우 미처리.
- **터치 타깃:** 모바일에서 상태 pill·아이콘 버튼(상세/재시도/삭제)이 44×44px 권장 최소 터치 타깃에 못 미칠 가능성 — 검증·확대 필요.
- **대비:** 회색 부제 텍스트(`#64748b` 계열)가 흰 배경에서 WCAG AA(4.5:1)를 만족하는지 소형 텍스트 기준 재확인 필요.

## 반응형 (Responsive) — 375px 실측

- 🔴 **네비게이션 붕괴:** 햄버거 메뉴 없이 5개 nav 항목이 각각 2줄로 깨짐(운영 현/황, 문서 업로/드, 폴더 일괄 변/환, 회의/록, 작업/큐). "새 변환" 버튼도 "새 변/환"으로 줄바꿈.
- 🟡 **스탯 카드 세로 스택:** 6개 카드가 세로로 쌓여 대시보드가 과도하게 길다(스크롤 부담). 2열 그리드가 적합.
- 🟡 **테이블 반응형:** 작업 큐/배치의 다열 테이블이 좁은 화면에서 어떻게 접히는지 확인 필요(가로 스크롤 vs 카드 변환).

권장: `@media (max-width: 720px)`에서 nav를 햄버거/드로어로 전환, 스탯 카드 2열, 테이블은 카드형으로.

## 잘된 점

- 핵심 변환 경로(랜딩→업로드→큐→상세)의 라이트 SaaS 디자인이 깔끔하고 카드 레이아웃이 일관적이다.
- 업로드의 "정밀 변환 / 빠른 변환" 모드 선택 카드가 명료하고 선택 상태가 시각적으로 분명하다.
- 일괄 변환의 결과 분류(선택/등록 가능/큐 등록/성공/저품질 의심/재시도 가능/제외·실패) 7분류는 운영자 관점에서 잘 설계된 정보 구조다.
- 상세 화면의 메타데이터(형식/확장자/MIME/크기/엔진/변환 시간/생성일) 표가 명확하다.

## 발견 사항 (우선순위)

### [DSN-01] 디자인 시스템 이원화 + 브랜드명 혼재
- **우선순위: P0(공개배포 차단)** · 근거: 회의록 화면이 다크+골드 테마 + "Bzengage Minutes/Whisper Meeting OS" 별도 브랜드. 나머지 전 화면은 라이트 블루 "hwptopdf".
- 권장안: 회의록을 앱 디자인 토큰으로 리스킨 + 단일 브랜드 통일. 외부 배포 시 회의록 미완성이면 [PO-01]대로 nav에서 제외.
- 기대 효과: 제품 신뢰도·일관성 회복.

### [DSN-02] 모바일 네비게이션 붕괴
- **우선순위: P1** · 근거: 375px에서 nav 항목·버튼이 2줄로 깨짐(실측).
- 권장안: 720px 이하에서 햄버거/드로어 네비게이션, 버튼 `white-space: nowrap`.
- 기대 효과: 모바일 사용성 확보(운영자가 이동 중 확인 가능).

### [DSN-03] 사용자 적대적 에러 메시지 (내부 인프라 노출)
- **우선순위: P1** · 근거: 상세 화면에 `http://localhost:8080/convert failed` 등 내부 체인 원문 노출(실측). 보안 [SEC-09]와 연계.
- 권장안: 사용자용 메시지 + 접기형 기술 상세 분리, 원문은 서버 로그.
- 기대 효과: 사용자 혼란 제거, 정보 노출 차단.

### [DSN-04] 랜딩이 핵심 차별점(품질 판정)을 전달 못함 + 목업 통계 오인
- **우선순위: P1** · 근거: 히어로가 "운영 큐에서 PDF 변환"만 강조. "성공률 94%"가 예시인데 라벨 없음. (PO-03과 동일 이슈의 시각 관점)
- 권장안: 히어로 카피를 "품질을 판정하는 변환기(passed/review/failed)"로, 기능 카드에 "품질 리포트·엔진 체인·검수" 추가, 통계는 실데이터 연동 또는 "예시" 명시.
- 기대 효과: 차별화 전달, 전환율↑.

### [DSN-05] review(저품질) 상태의 시각적 부재·불일치
- **우선순위: P1** · 근거: 작업 큐에 저품질 탭 없음(실측). 배치 요약엔 "저품질 의심" 카드 존재 → 불일치.
- 권장안: 큐에 저품질 탭 + 목록 품질 배지. passed/review/failed 3단계 상태 색상 체계 표준화.
- 기대 효과: 핵심 가치의 실사용 경로 완성.

### [DSN-06] 빈 상태(empty state) 빈약 — 온보딩 부재
- **우선순위: P2** · 근거: 큐/배치/회의록의 빈 상태가 텍스트 한 줄("변환할 폴더를 선택하세요" 등). CTA·샘플 유도 없음.
- 권장안: 일러스트 + 3단계 온보딩(업로드→상태→다운로드) + "샘플로 시험" CTA.
- 기대 효과: 첫 변환 성공까지 시간 단축(activation↑).

### [DSN-07] 대시보드 시각 위계 부재 + 추세 없음
- **우선순위: P2** · 근거: 6개 동일 크기 카드, 실패 1건짜리 도넛이 화면 절반. 정적 스냅샷.
- 권장안: 성공률/저품질 비율 1차 지표 강조 + 최근 7/30일 추세 라인. (PO-07 KPI 연계)
- 기대 효과: 운영 판단 지원.

### [DSN-08] 로그인/신뢰 요소 부재
- **우선순위: P2** · 근거: 로그인에 DEV_AUTH 진입점·약관·개인정보 링크 없음.
- 권장안: DEV_AUTH 진입 버튼(활성 시), 약관/개인정보/지원 링크 푸터. (PO-02 법적 요소와 연계)
- 기대 효과: 내부 온보딩 + 외부 신뢰 확보.

### [DSN-09] 접근성 개선 (색상 의존·터치 타깃·대비·오버플로우)
- **우선순위: P2** · 근거: 상태 색상 단독 의존, 회의록 텍스트 잘림, 모바일 터치 타깃 미검증.
- 권장안: 상태에 아이콘 병행, 터치 타깃 44px, 대비 AA 검증, 오버플로우 처리.

### [DSN-10] 디자인 토큰 미추출 + `styles.css` 비대

- 기대 효과: 리스킨·다크모드·유지보수 용이.

### [DSN-11] 삭제 버튼에 확인 절차 없음 — 데이터 유실 위험 🆕(2026-07-05 QA 실측)
- **우선순위: P1** · 근거: 작업 큐(`Jobs.tsx`)·작업 상세(`JobDetail.tsx`)의 "삭제" 버튼이 **확인 다이얼로그 없이 즉시** `DELETE /api/jobs/:id`(204)를 호출하고 원본·PDF·리포트를 영구 삭제. 브라우저 QA에서 `window.confirm`을 계측한 결과 **호출 0회** — 실수 클릭 한 번으로 복구 불가. 파괴적 액션인데 안전장치가 전무.
- 권장안: 삭제 전 확인 모달(또는 최소 `confirm`) + 가능하면 실행 취소(undo) 토스트. 대량 삭제는 체크박스+일괄 확인.
- 기대 효과: 우발적 데이터 유실 차단(운영자 신뢰).

### [DSN-12] 랜딩 히어로의 "새 변환" 버튼이 죽은 버튼 🆕(2026-07-05 QA 실측)
- **우선순위: P3** · 근거: 랜딩 히어로 미리보기 카드 안의 `<button>새 변환</button>`을 실제 클릭해도 아무 동작·이동이 없음(경로·해시 불변). 장식용 목업이지만 실제 클릭 가능한 버튼이라 사용자가 인터랙티브로 오인.
- 권장안: 실제 CTA(`/service/upload`)로 연결하거나, 비인터랙티브 요소(예: `role`/포인터 이벤트 제거)로 바꿔 클릭 어포던스를 없앰.
- 기대 효과: 헛클릭·혼란 제거.
