## 안건 1 · 회의록(Meetings) WIP 방향 [P0-2]

**배경.** 주 내비게이션(`Layout.tsx:10`)에 "회의록"이 정식 노출돼 있으나, 백엔드는 0줄이고 영속화는 `localStorage`뿐인 **클라이언트 목업**이다. 브라우저 마이크로 실제 음성을 녹음하고 평문 저장하는데 동의 게이트·접근 제어가 없다(설계 문서는 완전한 백엔드를 명시했으나 미구현). 디자인도 앱 전체(라이트 블루)와 다른 다크+골드 테마 + 별도 브랜드명("Bzengage Minutes"/"Whisper Meeting OS"). 비전 문서에 회의록 근거 없음 → 현재는 **스코프 크리프**. QA에서 초대 링크 가짜 성공·죽은 링크 등 버그도 확인([DEV-12]).

| 선택지 | 내용 | 장점 | 단점/리스크 |
|---|---|---|---|
| **A. 폐기(제거)** | nav·라우트·`pages/meetings/` 제거 | 표면 최소화, 개인정보 리스크 즉시 제거, 핵심(변환 검수)에 집중 | 이미 쓴 설계·구현 매몰 |
| **B. labs 격리(권장)** | `/labs`로 이동 + `VITE_ENABLE_MEETINGS` 플래그로 **외부 빌드 제외** + "실험·서버 미저장·민감정보 금지" 경고 | 탐색 유지하면서 공개 배포 차단 해제, 되돌리기 쉬움 | 미완성 코드가 리포에 잔존(유지보수 부채) |
| **C. 정식 승격** | 비전 문서 갱신 → 설계대로 백엔드(동의·접근제어·STT)·리스킨 구현 | 제품 확장(문서 운영 플랫폼) | 대형 투자, **핵심 차별점(검수 UI)보다 우선순위 역전**, 공개 배포 대폭 지연 |

**트레이드오프 핵심.** 공개 배포를 빠르게 열려면 A/B. C는 "이 서비스를 변환기에서 문서 운영 플랫폼으로 확장한다"는 **전략 결정**이 선행돼야 하며, 그 경우에도 README 로드맵의 검수 UI([PO-05])를 먼저 끝내는 게 순서상 맞다.

**권장: B(labs 격리) — 단기 배포 차단 해제 + 옵션 보존.** 이후 별도로 C 여부를 전략 안건으로 판단.

**결정 시 후속(Codex 스펙 전환).**
- A → nav/라우트/컴포넌트 제거 + `packages/shared/src/meeting*` 정리, 테스트 갱신.
- B → 라우트 `/labs/meetings` 이동, `VITE_ENABLE_MEETINGS` 게이팅, 경고 배너, 프로덕션 빌드에서 nav 숨김.
- C → 별도 기획(비전 문서 갱신) → 설계서 기반 풀스택 스펙(대형).

**결정 질문:** 회의록은 (a)폐기 / (b)labs 격리 / (c)정식 승격 중 무엇인가? (b/c면 외부 배포 포함 여부)

## 안건 2 · 데이터 보존 정책 + 법적 고지 [P0-3]

**배경.** `business-policy.md`는 업로드 원본을 "Confidential"로 규정하나, 실제 보존은 `DATA_RETENTION_DAYS=30` 스윕(`server.ts:71`)으로 30일 후 삭제된다. 그런데 **UI 어디에도 보존 기간·삭제 정책·개인정보 고지가 없고**, 약관/개인정보처리방침/문의 채널/사용량 한도 안내도 없다. 공공기관·기업 타겟에는 조달·규제상 필수([PO-02]).

| 결정 축 | 선택지 | 비고 |
|---|---|---|
| **보존 기간** | (a)현행 30일 유지 / (b)더 짧게(예 7일) / (c)사용자·기관별 설정 | 규제·조달 요건에 종속. 기본 30일은 무난하나 기관 요구시 단축 |
| **즉시 삭제** | 사용자가 job 삭제 시 원본+PDF+리포트 cascade(이미 구현, [P1-8]로 확인 다이얼로그 추가됨) | UI에 "즉시 삭제" 안내 노출 필요 |
| **법적 문서** | 이용약관 / 개인정보처리방침 (필수) | 페이지 신설 + 푸터 링크 |
| **LLM/외부 전송 고지** | 회의록 STT가 브라우저→외부(Google 등) 전송([SEC-08]) | 회의록 유지 시 동의 UI 필수 |
| **지원·한도 안내** | 문의 이메일, 활성 50개·재시도·rate limit 초과(413/429) 친화 메시지 | UI 카피 |

**트레이드오프.** 보존 정책 자체는 코드로 이미 강제되나(30일 스윕), **고지·법적 문서 부재가 배포 차단**. 정책 값(기간)은 타겟 규제에 따라 정해야 하므로 사용자 결정 필요.

**권장.**
- 보존 기간: **현행 30일 유지**(b/c는 실제 고객 요건 확인 후). UI에 "업로드 문서·결과는 30일 후 자동 삭제, 언제든 수동 즉시 삭제 가능" 명시.
- 이용약관·개인정보처리방침 **페이지 신설 + 푸터 링크**(초안은 도메인·운영주체 확정 후).
- 회의록을 남길 경우([안건1]) STT 외부 전송 동의 UI 필수.
- 413/429·한도 초과 친화 메시지.

**결정 시 후속(Codex 스펙 전환).** 정적 법적 페이지 + 푸터 링크 컴포넌트, 업로드/배치 화면 보존 고지 배너, 에러 메시지 카피(413/429). *(법적 문서 문안 자체는 운영주체·관할 확정 후 별도.)*

**결정 질문:** ① 보존 기간(30일 유지?) ② 운영 주체/도메인(약관·개인정보 문안에 필요) ③ 지원 채널(이메일 등)?

## 안건 3 · 랜딩 가치 제안 + 통계 표기 [P0-5]

**배경.** 랜딩(`Landing.tsx`)이 "운영 큐에서 PDF로 변환"만 강조하고, **유일한 차별점인 "품질 판정(passed/review/failed)"이 첫 화면에 없다**([PO-03]/[DSN-04]). 히어로 우측 목업 통계("성공률 94%")는 하드코딩인데 "예시" 라벨이 없어 실데이터로 오인될 수 있다(과장광고 리스크).

| 결정 축 | 선택지 | 비고 |
|---|---|---|
| **가치 제안 카피** | "품질을 판정하는 변환기"로 재정렬(권장) vs 현행 유지 | 차별화 전달 여부 |
| **통계 표기** | (a)실데이터 연동(`/api/stats`) / (b)"예시" 명시 라벨 / (c)제거 | (a)는 비로그인 랜딩에서 집계 노출 정책 필요 |

**트레이드오프.** 카피 재정렬은 저비용·고효과(전환율·타겟 적합성). 통계는 (a)실데이터가 이상적이나 랜딩은 비인증 페이지라 **전체 집계를 공개로 노출할지** 정책 결정 필요(민감할 수 있음). (b)"예시" 라벨이 가장 안전·저비용.

**권장.**
- 히어로 카피: **"변환 성공이 아니라 *품질*을 판정합니다 — passed/review/failed"** 로 교체, 기능 카드에 "품질 리포트·엔진 체인·검수" 추가.
- 통계: **(b) "예시" 라벨 명시**(단기). 실데이터 공개는 별도 정책 판단 후.

**결정 시 후속(Codex 스펙 전환).** `Landing.tsx` 카피·기능 카드 개편(디자인은 Fable 5가 설계 제공), 목업 통계에 "예시" 라벨 또는 실데이터 연동.

**결정 질문:** ① 가치 제안 재정렬 승인? ② 통계는 (a)실데이터 / (b)"예시" 라벨 / (c)제거 중?
