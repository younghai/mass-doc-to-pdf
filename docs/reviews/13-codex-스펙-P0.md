## SPEC-F · P0-2 회의록 labs 격리 (외부 빌드 제외)

**근거:** [PO-01]/[DSN-01]. 백엔드 없는 목업이 주 nav 노출 + 마이크 평문 저장 + 별도 디자인. 외부 공개 차단.

**대상 파일**
- `apps/web/src/components/Layout.tsx` — nav 배열(`{ to: "/service/meetings", label: "회의록" }` 라인 ~10).
- `apps/web/src/App.tsx` — `/service/meetings` 라우트(라인 51~57).
- `apps/web/.env.example` / Vite env — `VITE_ENABLE_MEETINGS` 신설.
- `apps/web/src/pages/Meetings.tsx` — 상단 경고 배너.
- `apps/web/src/pages/Meetings.test.tsx`, `App`/`Layout` 테스트 — 플래그 반영.

**변경 설계**
1. `VITE_ENABLE_MEETINGS`(기본 미설정=off) 도입. `const meetingsEnabled = import.meta.env.VITE_ENABLE_MEETINGS === "1"`.
2. **nav 게이팅:** off면 "회의록" nav 항목 미렌더. 라벨을 "회의록"→"회의록 (실험)"로(on일 때).
3. **라우트 이동/게이팅:** 경로를 `/service/meetings` → `/labs/meetings`. off면 라우트 미등록 또는 `/service`로 redirect.
4. **경고 배너:** Meetings 페이지 최상단에 "실험 기능 · 서버에 저장되지 않음(브라우저 로컬) · 민감/기밀 정보 입력 금지 · 음성이 브라우저 외부(STT)로 전송될 수 있음" 고정 배너([SEC-08] 고지 겸용).
5. **프로덕션 빌드:** 배포 스크립트/compose의 web 빌드에서 `VITE_ENABLE_MEETINGS`를 설정하지 않음(=제외). `docker-compose.prod.yml`·standalone 빌드 확인.

**수용 기준**
- 플래그 off(기본): "회의록" nav 없음, `/labs/meetings`·`/service/meetings` 접근 불가(리다이렉트), 프로덕션 빌드에 회의록 진입점 부재.
- 플래그 on: `/labs/meetings`에서 접근 가능 + 경고 배너 상시 노출.
- 데스크톱/기존 변환 플로우 무영향.

**테스트 조건 (TDD)**
- `Layout`/`App`: 플래그 off일 때 회의록 nav·라우트 부재, on일 때 존재(env 모킹).
- 기존 `Meetings.test.tsx`는 플래그 on 컨텍스트로 실행되도록 셋업 조정.

**위험**
- Vite `import.meta.env` 모킹(vitest) 셋업 필요. 기존 Meetings 테스트가 무조건 렌더 가정 시 조정.
- **전략 결정 유보:** 정식 승격(C안)을 택하면 이 스펙 대신 별도 풀스택 기획 필요.

## SPEC-G · P0-3 데이터 보존 고지 + 법적 페이지

**근거:** [PO-02]. 보존/삭제 고지·약관·개인정보처리방침·지원·한도 안내 부재 → 조달/규제 차단.

**대상 파일**
- 신규 `apps/web/src/pages/Terms.tsx`, `apps/web/src/pages/Privacy.tsx` + `App.tsx` 라우트(`/terms`, `/privacy`, 비인증 접근).
- `apps/web/src/components/Layout.tsx` — 푸터에 약관·개인정보·문의 링크(신규 푸터 or 기존 확장).
- `apps/web/src/pages/Upload.tsx`, `apps/web/src/pages/BatchUpload.tsx` — 보존 고지 배너.
- `apps/web/src/api/client.ts` 또는 에러 표시부 — 413/429 친화 메시지.

**변경 설계**
1. **법적 페이지(정적):** Terms/Privacy 컴포넌트. 문안은 `<TBD-운영주체>`, `<TBD-도메인>`, `<TBD-관할>`, `<TBD-문의이메일>` 플레이스홀더 + 데이터 처리(업로드→변환→30일 보존→자동삭제, LLM/외부 전송 시 고지) 골격. **정식 법무 문안은 별도**(운영주체 확정 후).
2. **푸터 링크:** 약관 · 개인정보처리방침 · 문의(`mailto:<TBD-문의이메일>`).
3. **보존 고지:** 업로드/배치 화면에 "업로드 문서·결과 PDF는 30일 후 자동 삭제되며, 작업 삭제로 즉시 제거할 수 있습니다"(코드 기본값 `DATA_RETENTION_DAYS=30`과 일치).
4. **한도 카피:** 413(크기 초과)→"파일 크기가 20MB를 초과합니다", 429(대기 한도/rate limit)→"변환 대기 한도를 초과했습니다. 완료된 작업 확인 후 재시도하세요" — 이미 서버 메시지 있는 경우 클라이언트가 상태코드별로 친화 표기.

**수용 기준**
- `/terms`·`/privacy` 비인증 접근 가능, 푸터 링크 동작.
- 업로드/배치에 보존 고지 노출.
- 413/429 시 한국어 친화 메시지(내부 정보 없음, [SPEC-A]와 정합).

**테스트 조건**
- web: Terms/Privacy 라우트 렌더, 푸터 링크 존재, 보존 고지 텍스트, 에러 상태코드→메시지 매핑.

**위험**
- 법무 문안 미확정 시 플레이스홀더로 배포 불가 — 운영주체/도메인 확정이 실제 배포 선행조건([P0-3] 결정 질문).

## SPEC-H · P0-5 랜딩 가치 제안 재정렬 + 통계 라벨

**근거:** [PO-03]/[DSN-04]. 차별점(품질 판정) 미전달 + 목업 통계 오인.

**대상 파일**
- `apps/web/src/pages/Landing.tsx` — 히어로 카피, 기능 카드, 목업 통계.
- `apps/web/src/pages/Landing.test.tsx` — 카피 검증.

**변경 설계**
1. **히어로:** "HWP와 Office 문서를 운영 큐에서 PDF로 변환" → **"변환 성공이 아니라 *품질*을 판정합니다 — passed · review · failed"** 중심. 부제에 "저품질(review)을 자동 분리해 검수" 강조.
2. **기능 카드:** 기존 3개(HWP/Office/운영 큐)에 **품질 리포트 · 엔진 체인(정밀→fallback) · 검수 워크플로우** 관점 추가/교체.
3. **통계:** 히어로 목업 "성공률 94%" 등 하드코딩에 **"예시" 배지/라벨** 부착(과장광고 방지). *(실데이터 연동은 비인증 랜딩 노출 정책 판단 후 별도 — 현 결정은 "예시".)*
4. (디자인 상세는 Fable 5가 별도 제공 가능 — 카피/구조는 위 기준.)

**수용 기준**
- 첫 화면에 "품질 판정" 차별점이 3초 내 전달(히어로·카드).
- 목업 통계에 "예시" 라벨 명시.
- 기존 랜딩 링크/CTA(서비스 사용하기 등) 동작 유지.

**테스트 조건**
- `Landing.test.tsx`: 히어로에 "품질"/"review" 카피 존재, 통계에 "예시" 라벨 존재.

**위험**
- 낮음(프론트 카피/구조). 디자인 토큰 미추출 상태라 스타일은 기존 재사용.
